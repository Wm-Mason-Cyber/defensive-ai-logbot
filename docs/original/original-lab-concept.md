# AP Cybersecurity Lab: Defensive AI & Automated Incident Response

Here is a complete, copy-pasteable lab architecture designed to run seamlessly inside a single Docker network on student machines with **6GB VRAM** video cards.

By utilizing **`llama3.2:3b`** running via Ollama on the host machine, the Docker container isolates the attacker simulation, the web server, and the mitigation broker without overloading the student’s GPU.

---

## Lab Topology & Architecture Overview

To mimic an enterprise environment without melting a 6GB VRAM GPU, this lab separates high-speed networking from low-speed probabilistic AI reasoning:

\[ Attacker Container \] \---\> (High-Speed Traffic) \---\> \[ Nginx Web Server Container \]  
                                                               |  
                                                   (Raw JSON Log Volume)  
                                                               v  
\[ AI Defend Broker \]  \<==== (Low Volume Filter) \<=== \[ Log Tail Agent (Host) \]  
       |                                                       |  
 (Ollama / Llama 3.2 3B)                        v  
       \+=================\> (Deterministic Trigger) \===\> \[ Automated Firewall Block \]

1. **The Attacker (Container 1):** Runs a multi-threaded fast attack script hitting Nginx.  
2. **Nginx Web Server (Container 2):** Processes requests and writes structured JSON logs.  
3. **The Tail Agent & Filter (Host Machine):** Drops `200 OK` volume entirely. It groups *only* `401 Unauthorized` entries into tiny windows, sending a heavily compressed context packet to the AI engine to strictly honor the **low-volume** target.  
4. **The AI Engine (Host Ollama):** Analyzes the intent of the compressed batch, returning a strict structural payload.  
5. **The Incident Response Catch:** The script parses the structural text file generated by the AI, validates the alert, and automatically triggers an API block against the malicious container.

## Part 1: The Docker Orchestration File

Create a file named `docker-compose.yml`. This exposes the Nginx logs directly to the host machine so the local Python AI agent can read them without installing complex container log forwarding chains.

```
version: '3.8'

services:
  nginx-target:
    image: nginx:alpine
    container_name: nginx-server
    ports:
      - "8080:80"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
      - ./logs:/var/log/nginx
    networks:
      - cyber-lab-net

  attacker-bot:
    image: python:3.11-slim
    container_name: attacker-container
    depends_on:
      - nginx-target
    volumes:
      - ./attack_script.py:/attack_script.py:ro
    command: python /attack_script.py
    networks:
      - cyber-lab-net

networks:
  cyber-lab-net:
    driver: bridge

```

## Configuration A: Structured JSON Nginx (`nginx.conf`)

This configures Nginx to drop traditional flat logs and output perfectly formed JSON objects.

```
events { worker_connections 1024; }

http {
    log_format json_cyber escape=json
        '{"time":"$time_iso8601","source_ip":"$remote_addr","user":"$remote_user","uri":"$request_uri","status":"$status"}';

    access_log /var/log/nginx/access.log json_cyber;
    error_log /var/log/nginx/error.log warn;

    server {
        listen 80;
        
        # Simulated Protected Resource
        location /admin/login {
            auth_basic "Secure Classroom Console";
            auth_basic_user_file /etc/nginx/.htpasswd; # Left intentionally missing to force 401s
        }

        # Simulated Public Resource
        location / {
            return 200 '{"message": "Welcome to the public portal"}';
        }
    }
}
```

## Configuration B: High-Volume Attacker Script (`attack_script.py`)

This runs continuously inside the attacker container. It mixes valid, fast traffic with stealthy, aggressive authentication brute-forcing.

```py

import random
import http.client

def send_request(method, path, headers=None):
    try:
        conn = http.client.HTTPConnection("nginx-target", 80)

        response = conn.getresponse()
        response.read() # clear buffer
        conn.close()

        pass

    # 1. Background Noise / Normal Activity (High speed, ignored by AI)

    # 2. Focused Brute-Force Burst (Targets the protected endpoint)
```

## Part 3: Host Pipeline & "Catching" the AI Output

Students run this Python pipeline (`ai_soc_broker.py`) on their **host machine**. It streams logs, compresses the data into a micro-batch, and pipes the output into a local file system tracker (`/alerts`) which can trigger an automated defensive fallback.

```py
import os
import json
import time
import ollama

LOG_FILE = "./logs/access.log"
ALERT_DIR = "./alerts"
MODEL_NAME = "llama3.2:3b"
BATCH_WINDOW = 5 # Small window to ensure immediate feedback for students

os.makedirs(ALERT_DIR, exist_ok=True)

def parse_and_mitigate(ai_text):
    """Parses structural text to simulate an active Endpoint/Firewall Catch."""
    lines = ai_text.strip().split("\n")
    status = "SAFE"
    target_ip = "UNKNOWN"
    
    for line in lines:
        if "[STATUS]" in line:
            status = "ALERT" if "ALERT" in line.upper() else "SAFE"
        if "[ATTACKER_IP]" in line:
            target_ip = line.split("]")[-1].strip()

    if status == "ALERT" and target_ip != "UNKNOWN":
        alert_file = os.path.join(ALERT_DIR, f"block_{int(time.time())}.json")
        alert_payload = {"timestamp": time.time(), "block_ip": target_ip, "reason": "AI Confirmed Brute Force"}
        
        with open(alert_file, "w") as af:
            json.dump(alert_payload, af, indent=4)
        
        print(f"🔒 [AUTOMATED REMEDIATION]: Wrote firewall block rule for {target_ip} to {alert_file}")

def run_ai_analysis(batch):
    formatted = json.dumps(batch, indent=2)
    prompt = f"""
    Analyze these filtered Nginx 401 events for automated cracking behaviors.
    Logs:
    {formatted}
    
    Respond STRICTLY in the following format:
    [STATUS] ALERT or SAFE
    [ATTACKER_IP] Input the malicious source IP address
    [EXPLANATION] One-sentence technical rationale
    """
    try:
        start = time.time()
        res = ollama.generate(model=MODEL_NAME, prompt=prompt)
        print(f"\n🧠 [AI Inference Engine Completed in {time.time()-start:.2f}s]")
        raw_output = res['response'].strip()
        print(raw_output)
        parse_and_mitigate(raw_output)
    except Exception as e:
        print(f"Error handling AI request: {e}")

def tail_logs():
    print(f"🤖 Initializing Defensive SOC Broker using {MODEL_NAME}...")
    # Wait for the docker-compose to spin up and create the log file
    while not os.path.exists(LOG_FILE):
        time.sleep(1)
        
    with open(LOG_FILE, "r") as f:
        f.seek(0, os.SEEK_END)
        current_batch = []
        last_flush = time.time()
        
        while True:
            line = f.readline()
            if line:
                try:
                    data = json.loads(line.strip())
                    # LOW VOLUME CONCEPT: Aggressively filter out standard 200 traffic here
                    if data.get("status") == "401":
                        current_batch.append(data)
                        print(f"📊 Filter captured anomaly: 401 on {data['uri']}")
                except json.JSONDecodeError:
                    continue

            if time.time() - last_flush >= BATCH_WINDOW:
                if current_batch:
                    run_ai_analysis(current_batch)
                    current_batch = []
                last_flush = time.time()
            time.sleep(0.05)

if __name__ == "__main__":
    tail_logs()

```

## Part 4: Classroom Briefing & Scale Talk

When handing this lab to your AP Cyber students, use this framing to explain how this concept transforms when scaled from a single 6GB student machine to an enterprise infrastructure.

## The Problem: Why can't we scale this setup directly?

* **The Math:** If a web cluster receives **10,000 requests per second**, passing every event to an LLM taking 1.5 seconds per prompt would instantly crash the infrastructure.  
* **The Token Cost:** Sending millions of raw log strings to an AI model introduces severe billing overhead and unmanageable resource depletion.

## The Enterprise Solution: How this translates to real SOCs

* **The Aggressive Sieve:** Real architectures use ultra-fast, deterministic tools (**Siemens**, **Vector**, or **Splunk Processing Language**) to drop \$99.9\\%\$ of predictable data at the edge.  
* **The Heuristic Trigger:** The local pipeline uses a Python script to screen out `200` responses. In an enterprise, an IAM system or firewall filters traffic until a rule-base flags an aggregate threshold violation (e.g., 50 failures in 2 seconds).  
* **The AI Tier Allocation:** Only when a highly optimized deterministic script flags a nuanced correlation is an AI engine context-called to determine user intent, verify a false positive, or map the behavior pattern directly to a **Mitre ATT\&CK** matrix phase.
